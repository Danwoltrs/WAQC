## Issues Found (BR-025808/26 as test case)

### BUG 1: Certificate record not created after Validate & Certify
The cupping finalize flow updates `workflow_stage` to "certified" and `status` to "approved", but does NOT create a record in the `certificates` table. This causes a cascade of downstream failures:
- Certificate does NOT appear on the `/certificates` page
- Sample detail page shows Certificate Status as "Pending" with "Generate" button (even though Stage: certified)
- No download/view certificate buttons on the samples list page (conditioned on `sample.certificate_id`)

**Root cause**: The finalize route (`/api/cupping/finalize`) updates sample workflow_stage but doesn't call the certificate creation logic (POST `/api/samples/[id]/certificate`). The certificate POST route exists and works, but is not called automatically.

**Fix**: Either (a) have the finalize route also create the certificate record, or (b) fix the sample detail page to recognize certified stage even without a certificate record and allow generating. Currently the "Generate" button does appear for `workflow_stage === 'certified'` when `certificate_id` is null, but the overall status badge misleadingly says "Pending".

**Files**: `src/app/api/cupping/finalize/route.ts`, `src/app/api/samples/[id]/certificate/route.ts`

### BUG 2: Sample page not showing Cupping & Grading scores
The sample detail page shows "No cupping scores available" even though the certificate PDF has valid cupping data (all attributes scored at 3.0-3.25).

**Root cause**: The aggregate endpoint (`/api/cupping/scores/aggregate`) may be filtering to only currently assigned cuppers from an active session, and after finalization the session is closed or cuppers are unassigned. The data is in `cupping_scores` table but the aggregate query is too restrictive.

**Files**: `src/app/api/cupping/scores/aggregate/route.ts`, `src/app/samples/[id]/page.tsx`

### BUG 3: Certificate Status shows "Pending" when stage is "certified"
The Certificate Status card on the sample detail page checks `sample.certificate_id` to determine if certified. When the finalize flow doesn't create a certificate record, it shows "Pending" even though the sample is certified.

**Fix**: Show "Certified (no certificate generated yet)" when `workflow_stage === 'certified'` but `certificate_id` is null. Keep the Generate button prominent.

**Files**: `src/app/samples/[id]/page.tsx` (lines 1057-1133)

### UI 4: Supply Chain section on sample page
- Remove the "Supply Chain" CardHeader/CardTitle — just show the table directly inside the card
- Always show Seller and Shipper rows (currently Shipper is hidden when `same_seller_shipper` is true). Show `-` as the name if no data, so users can still edit and add a shipper later
- Keep the same editable functionality

**Files**: `src/app/samples/[id]/page.tsx` (lines 1037-1055), `src/components/samples/supply-chain-edit-table.tsx` (line 343 conditionally hides Shipper)

### BUG 5: Certificate PDF missing supply chain entities
The generated PDF for BR-025808/26 shows only "Wolthers" on the left with no other entities. The importer (OFI) and roaster (National DCP) are missing. The `CertificateSupplyChainRow` component only renders entities with non-null names, so the data fetching in `certificate-data.ts` is not resolving the entities properly.

**Root cause**: Likely the `getCertificateData()` function in `certificate-data.ts` is not finding the importer/roaster because they may be stored via different FK relationships (e.g., importer_id vs client-type fallback).

**Files**: `src/lib/certificate-data.ts`, `src/components/pdf/certificate/certificate-supply-chain-row.tsx`

### UI 6: Certificate PDF layout improvements
**6a. Attribute labels truncated**: "Fragrance/Aro..." — the `leftSection` width is only 85px, too small for "Fragrance/Aroma". Increase to ~110px.

**6b. Chart needs to shift right**: The chart SVG is positioned too close to the attribute labels, causing the labels to overlap. Add more spacing.

**6c. Clean Cup/Uniform Cup/Faults/Taints too far right**: The `verticalSeparator` has `marginLeft: 235px` which pushes these elements far from the chart. Reduce to bring them closer.

**6d. Last score diamond gets clipped**: The diamond/rhombus marker at the right edge of the SVG is clipped because the SVG width equals `barWidth` exactly, but the diamond extends `RHOMBUS_SIZE (4px)` beyond. Add padding to SVG width or use `overflow: visible`.

**Files**: `src/components/pdf/certificate/certificate-cupping-chart.tsx` (styles at lines 68-69 for leftSection width, line 34 for verticalSeparator marginLeft, line 112 for MAX_BAR_WIDTH, line 199 for SVG width)
