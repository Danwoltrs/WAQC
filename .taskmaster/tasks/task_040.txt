# Description: Fix PostgreSQL error 42703 ('record new has no field client_id') in both trigger_sync_client_to_supply_chain and trigger_recalculate_on_client_pricing_change triggers by removing invalid ON CONFLICT logic and re-enabling both triggers currently disabled via migrations 117 and 122.
# Details:
**PROBLEM ANALYSIS:**

Both triggers are currently disabled and contain buggy code causing SQL error 42703:

1. **trigger_sync_client_to_supply_chain** (Migration 056, disabled in 117):
   - Original issue: Line 26-34 in migration 056 uses `ON CONFLICT (id) DO UPDATE WHERE exporters.client_id = NEW.id`
   - Problem: NEW is a `clients` record, not an `exporters` record, so NEW.id refers to client ID, not exporter ID
   - The ON CONFLICT WHERE clause is trying to reference NEW in the context of the exporters table, which is invalid
   - Migration 112 attempted a fix by removing ON CONFLICT entirely and using explicit SELECT/UPDATE logic

2. **trigger_recalculate_on_client_pricing_change** (Migration 029, disabled in 122):
   - Function: recalculate_client_sample_fees() at lines 42-52 in migration 029
   - Triggered on: UPDATE OF pricing_model, price_per_sample, price_per_pound_cents ON clients
   - Current code: Updates samples table by recalculating fees when client pricing changes
   - Error suggests the function may have similar NEW context issues or conflicts with other triggers

**ROOT CAUSE:**
The original migration 056 used `ON CONFLICT (id) DO UPDATE SET ... WHERE exporters.client_id = NEW.id` which is PostgreSQL invalid syntax. The WHERE clause in ON CONFLICT cannot reference NEW from the parent trigger context - it operates on the conflicting row in the target table (exporters/importers/roasters), not the triggering row (clients).
